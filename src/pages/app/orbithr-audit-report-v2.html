M-002 Medium Backend Recruitment — Integration Test
TenantIntegrationController::test() only pings public URLs, not authenticated provider endpoints
The test method now makes a Guzzle request, but only to a public URL (e.g., https://slack.com/api/api.test) — not an authenticated call with the tenant's actual credentials. A valid connection ping tells you the provider is reachable on the internet, not that the stored credentials are valid. An expired Slack token would still pass this test.
 TenantIntegrationController.php:136–175 Integration connection tests pass for providers with invalid or expired credentials, giving false confidence.
M-003 Medium Backend Payroll — Payslip
Payslip bulk-email has no rate limiting or batch queuing
PayslipController::bulkEmail() iterates over all payslips in a cycle and calls Mail::to()->send() synchronously in a loop. For tenants with hundreds of employees this will timeout or trigger rate limiting from the mail provider. Emails should be dispatched to a queue. The method also does not verify PDF existence (same issue as H-007) for each payslip in the batch.
 PayslipController.php:281–325 (bulkEmail) Bulk payslip emailing will timeout on large employee counts. Some employees receive emails without PDF attachments if payslips weren't generated.

M-005 Medium Backend Payroll — Cycles
Payroll cycle "suggest-next" route ordering causes 404
In routes/api.php, the route GET /payroll/cycles/suggest-next is defined AFTER GET /payroll/cycles/{id}. Laravel will match suggest-next as the {id} parameter and attempt to find a cycle with ID "suggest-next", returning a 404. The named parameter route must come before the wildcard.
 routes/api.php:435–439 (route ordering issue) The "Suggest next cycle dates" feature in the Payroll UI always returns 404.
M-006 Medium Frontend Employee Profile — Tabs
EmployeeProfile "Performance" tab calls generic /performance/goals — not filtered by employee
The performance tab fetches GET /api/performance/goals with no employee_id filter. This returns all goals for the authenticated user, not the employee being viewed. When an HR manager views a specific employee's profile, the performance tab shows the HR manager's own goals, not the employee's goals.
 orbithr-web/src/pages/app/EmployeeProfile.vue (performance tab fetch) HR managers see their own performance goals in the employee profile's performance tab — wrong data shown.

L-002 Low Backend Leave — Proration
Leave proration setting uses global Setting model — no per-tenant isolation guarantee
The proration mode is stored in a generic Setting key/value store. Depending on how this model scopes its records, the setting may not be isolated per tenant. If the Setting model does not apply a TenantScope global scope, all tenants would share the same proration mode.
 Services/LeaveManagementService.php:551–572 (getProrationMode) If Setting model is not tenant-scoped, changing proration mode for one tenant changes it for all.
L-003 Low Backend AI — Chat
AiController rule-based fallback responses are generic — not tenant-aware
When neither ANTHROPIC_API_KEY nor OPENAI_API_KEY is configured, the AI chat falls back to keyword-matched static responses. These responses reference generic features (e.g., "Leave module") without knowing what modules the tenant has activated. A tenant without the Leave module would receive instructions to use a feature they don't have.
 AiController.php (fallbackReply method) Minor UX issue — fallback responses may reference unavailable features.
L-004 Low Frontend Payroll
Payroll Advances tab uses text input for employee ID instead of a searchable dropdown
The "Request Advance" modal uses a plain number input for employee ID, requiring the admin to know the employee's numeric ID. It should use a searchable employee selector (as other forms in the app do) to provide name/code lookup.
 orbithr-web/src/pages/app/Payroll.vue (advance form) Poor UX for advance requests — admins must look up employee IDs manually.
L-005 Low Backend Payroll — Cycles
PayrollController::suggestNextCycle route registered after wildcard route
In routes/api.php, GET payroll/cycles/suggest-next is registered at line 439 but GET payroll/cycles/{id} is at line 434. Laravel resolves routes top-to-bottom; suggest-next will be captured as the {id} parameter and return a model-not-found error. The suggest-next route must be moved before the {id} route.
 routes/api.php:434–439 GET /api/payroll/cycles/suggest-next always returns 404 or a model-not-found error.
